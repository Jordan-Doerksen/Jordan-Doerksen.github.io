What this is

§ 00

None of it is a product. Each one exists because something was annoying enough to fix — a rulebook that wouldn't stay in my head, a market I wanted to read without touching, a game I wanted to exist.

The count isn't the interesting part. What might actually be worth your time is the write-up behind most of them: what it's made of, how data moves through it, and which decisions you'd have to argue with to change it. If something here has nothing behind it, it says so — private, frozen, or retired, never a dead link.

How the write-ups work

§ 05

Each one that's written up gets a single page, rendered from one JSON file by one template. Adding a project is an object in a list; writing it up is a file and a hand-drawn diagram. No page code changes, no build step.

  1. A list entry gives it a name, a section, an honest status, and one line of description.
  2. A project file adds the stack, the components, the data flow, and the decisions.
  3. A hand-drawn SVG shows how data actually moves — no diagram engine, no runtime deps.
  4. One template renders all three. If there's no write-up yet, the page says so.
